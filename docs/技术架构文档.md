# 技术架构文档

## 一、系统定位

面向学院教学管理端与学生备考端的双端闭环管理服务系统,以"进度可视化、帮扶精准化、备考智能化"为核心,覆盖考研全周期(择校-备考-初试-复试-调剂)。

## 二、技术栈

| 层 | 技术 | 版本 |
|----|------|------|
| 前端 | Vue 3 + Vite + Element Plus + ECharts + Pinia | Vue 3.4 / Vite 5 |
| 后端 | Node.js + NestJS + Prisma ORM | Node 18 / NestJS 10 |
| 数据库 | MySQL 8.0 | utf8mb4 |
| 缓存/限流 | Redis 7 | - |
| 部署 | Docker + Docker Compose | - |
| AI | 规则加权 + OpenAI 兼容 LLM API | 智谱 GLM / 通义 / DeepSeek |

## 四、数据库设计

### 4.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|---------|
| User | 用户(学生/导师/管理员) | role, departmentId, majorId, classId |
| StudentProfile | 学生背景(AI 输入维度) | undergraduateMajor, gpa, majorRank, currentStage |
| ProgressArchive | 进度档案(加密存储) | targetSchoolName(加密), examTotal, finalResult |
| ProgressHistory | 进度历史轨迹 | stage, snapshot |
| CheckInRecord | 周度打卡记录 | weekStart, status, stage, completedItems, difficulties |
| MakeupCheckInApplication | 补卡申请 | reason, status, approverId |
| StudyPlan | 备考计划(周/月) | weekKey, monthKey, tasks(JSON) |
| School | 院校 | name, tier, priorityWeight |
| MajorProgram | 招生专业 | majorName, reportRatio2025, reexamLine2025 |
| AIRecommendation | AI 推荐结果 | inputParams, result, llmSummary |
| AIRecommendationFeedback | 导师校准 | comment |
| Resource | 备考资源 | type, status, stage, majorName |
| HelpApplication | 帮扶申请 | type, content, status, assigneeId |
| HelpRecord | 帮扶记录 | content, effect |
| Alert | 异常预警 | type, status |
| NotificationLog | 站内信 | channel, title, content |
| KeyNodeReminder | 关键节点提醒 | nodeKey, remindAt |
| CheckInRule | 打卡规则配置 | period, requireStage, makeupEnabled |
| SystemConfig | 系统配置(KV) | key, value(JSON) |
| OperationLog | 操作日志 | userId, action, target, detail |
| BatchImport | 批量导入记录 | type, totalCount, successCount |

### 4.2 权限模型(RBAC)

```
UserRole:
  STUDENT          → 仅访问个人数据
  COUNSELOR        → 所负责班级学生
  MAJOR_MENTOR     → 本专业学生
  ACADEMIC_ADMIN   → 全院数据 + 资源管理
  SYS_ADMIN        → 全部权限 + 系统配置
```

权限隔离通过 `buildStudentScope` 方法实现,根据角色自动构建查询范围。

## 五、核心流程

### 5.1 周度打卡闭环

```
学生打卡提交 → 写入 CheckInRecord → 更新 ProgressArchive → 生成 ProgressHistory
                                                          ↓
每周五 18:00 Cron → 检查未打卡学生 → 批量推送提醒(站内信+企微+短信)
每周日 20:00 Cron → 检查逾期 → 生成 Alert 预警 → 推送逾期通知
每周一 Cron → 异常扫描(连续2周未打卡/进度无更新/15天未登录)→ 生成预警
```

### 5.2 AI 择校推荐

```
学生输入(本科专业/绩点/排名/地区/偏好/剩余时长)
  ↓
规则加权计算:
  专业相关性 35%(同专业 35 / 同大类 25 / 跨专业 12)
  历年录取数据 35%(复试线/招生人数/报录比)
  学生自身条件 30%(绩点/排名/院校层次匹配/剩余时长/地区)
  ↓
学院优先推荐加权(priorityWeight)
  ↓
分档:冲刺(≥130) / 稳妥(≥100) / 保底(<100),每档至少 3 个
  ↓
LLM API(可选)→ 生成自然语言综合建议
  ↓
持久化 → 导师可对每条推荐标注修正
```

### 5.3 多通道通知

```
触发事件(打卡提醒/逾期预警/关键节点/批量通知)
  ↓
读取 SystemConfig.notify_channels
  ↓
并行派发:
  ├─ 站内信(始终发送,批量 createMany 200/批)
  ├─ 企业微信(若启用,获取 access_token → 按手机号推送)
  └─ 短信(若启用,阿里云/腾讯云 SDK)
  ↓
失败不阻塞主流程,日志记录
```

### 5.4 离线缓存同步

```
学生提交打卡 → 网络异常 → localStorage 缓存(payload + timestamp)
  ↓
window.addEventListener('online') → 自动重试提交
  ↓
成功 → 清除缓存 + 刷新页面
失败 → 保留缓存等待下次重试
```

## 六、安全设计

| 层面 | 措施 |
|------|------|
| 认证 | JWT(12h 有效期),预留 CAS/SSO 接口 |
| 授权 | RBAC 三级权限隔离,数据范围自动构建 |
| 传输 | HTTPS(部署时配置 SSL),Helmet 安全头 |
| 存储 | AES-256-GCM 加密 PII 字段(targetSchoolName 等) |
| 限流 | Throttler 200 req/min/user |
| 审计 | OperationLog 全量操作留痕 |
| 备份 | 每日自动 mysqldump,保留 30 天 |
| 容错 | 离线缓存、LLM 兜底、企微失败兜底 |

## 七、性能设计

| 指标 | 设计 |
|------|------|
| 并发 | 500 学生 + 50 导师,连接池 20 |
| 响应 | 核心功能 ≤ 2 秒 |
| 批量 | 通知 200/批,企微 1000/批 |
| 索引 | CheckInRecord(studentId, weekStart, status)、Alert(studentId, status) |
| 分页 | 所有列表 API 支持分页,默认 20 条 |
| 缓存 | Redis 缓存 + 限流 |
| 压缩 | gzip 压缩响应 |
